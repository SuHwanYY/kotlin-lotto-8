# kotlin-lotto-precourse
---

## 기능 구현 목록

- 로또 구입 금액을 입력받고 1,000원 단위로 나누어 떨어지지 않는 경우 예외 처리

- 구입 금액에 해당하는 로또 발행 횟수만큼 로또를 발행
  - 숫자 범위는 1~45
  - 중복되지 않는 6개의 숫자를 랜덤으로 발행

- 당첨 번호와 보너스 번호 입력

- 당첨 결과 출력
  - 1등부터 5등까지 각각 조건에 따라 결과 출력

- 최종 수익률을 소수점 둘째 자리에서 반올림하여 출력

- 사용자가 잘못된 값을 입력했을 경우를 최종 점검

- ---

## 프로젝트 구조 및 역할

- **1. Application.kt**
  - 애플리케이션 실행 흐름 및 콘솔 입출력

- **2. Lotto.kt**
  - 로또 한 장의 객체
  - `fun values(): List<Int>`: 방어적 복사로 외부에서 참조할 수 있게하는 함수

- **3. LottoGenerator.kt**
  - 입력한 구입 금액만큼 로또를 생성
  - 난수 생성 책임을 분리해 테스트/유지보수 용이

- **4. PurchaseValidator.kt**
  - 구입 금액 검증
  - 금액 상수화 (`UNIT = 1_000`)

- **5. WinNumValidator.kt**
  - 당첨 번호, 보너스 번호 파싱 및 검증
  - 상수 : `MIN = 1, MAX = 45, REQUIRED_SIZE = 6`
  - 형식, 개수, 범위, 중복 등 모든 입력 제약을 명시적으로 `require`/예외로 처리

- **6. Rank.kt**
  - 등수 규칙 및 상금 관리
  - 열거형 값(`enum class`) 사용

- **7. ResultCalculator.kt**
  - 등수 집계 및 수익률 계산
  - **도메인 연산(집계/수익률/표기)**을 한 곳에 모아 응집도를 높임

## 새로 학습한 내용

- **enum class**
  - https://suhwan02.tistory.com/21

- **internal object**
  - `object` : 애플리케이션 전역에서 단 하나만 존재하는 **싱글톤 객체**를 만드는 키워드
  - `internal` : **같은 모듈 안에서만** 보이도록 하는 가시성 한정자
  - **사용 이유**
    - 전역적으로 한 번만 있어야 하는 도구를 감추고 싶을 때 사용
    - 객체를 매번 생성할 필요 없이 재사용 하면 되는 **유틸성 로직**

- **when 표현식**
  - 여러 조건을 간결하게 분기 처리할 수 있는 표현식

- **테스트 코드 작성**
  - 기능 단위로 동작을 검증하는 단위 테스트를 작성하며, `assertThat`과 `assertThrows` 등을 활용

## 소감
`internal object` 등을 처음 사용해보며 클래스 분리에도 신경쓰고 메서드가 단일 책임 원칙을 잘 따를 수 있게 노력해 보았지만 어려움이 많았고 아직 완벽에 가깝다고 느껴지지 않아 더욱 공부할 내용이 많다고 느껴졌습니다.

예외 처리 부분에선 `require()`로 깔끔하게 처리하기 전에 if문으로 여러 조건을 나눠서 로직을 작성하며 어려움도 있었습니다.

마지막으로, 저번 과제까지만 해도 테스트 코드를 사용하지 않았었는데 이번에 사용해보며 사용법을 익힐 때까지 많은 에러를 겪었습니다. 하지만 테스트 코드의 중요성을 체감할 수 있었고 앞으로도 코드의 문제를 빠르게 잡아내기 위해서 테스트 코드에 대한 학습을 꾸준히 해나갈 계획입니다.
